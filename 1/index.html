Project 01

Colorizing the
Prokudin-Gorskii Collection

Reconstructing early 20th-century Russian three-color glass plate photographs into full RGB images using image alignment, normalized cross-correlation and coarse-to-fine image pyramids.

Part 01

From Three Negatives to One Photograph

Prokudin-Gorskii's photographs were captured as three separate monochrome exposures through blue, green and red filters. The digitized glass plates therefore contain three vertically stacked images instead of a conventional RGB photograph. My goal was to recover the displacement between these exposures and stack them into one color image.

Step 01

Split

Divide the plate into three equal sections representing the Blue, Green and Red channels from top to bottom.

Step 02

Align

Search over possible x and y translations and find the displacement that gives the highest similarity.

Step 03

Stack

Apply the estimated shifts and combine the three channels into a final RGB image.

Reference

I used the Blue channel as the reference and aligned the Green and Red channels to it.

Search

Each possible displacement was tested within a user-specified x/y search window.

Metric

Normalized Cross-Correlation (NCC) was used to measure how well two channels matched.

Single-scale exhaustive search

I first implemented a simple exhaustive search on the smaller JPEG images. For every candidate displacement (dy, dx), the shifted channel is compared with the Blue reference. The displacement producing the highest NCC score is selected.

NCC = (u' · v') / (||u'|| · ||v'||)

I also ignored the outer borders when computing the similarity score. This prevents dark borders and scanning artifacts from influencing the alignment more than the actual scene.

What I learned

The exhaustive search is straightforward and works well when the images are small. With a search window of [-15, 15], there are 31 × 31 = 961 possible translations for each channel. The main limitation is that this becomes expensive as the image size and possible displacement increase. This led me to the next step: using an image pyramid to make the search more efficient.

Part 02

Coarse-to-Fine Image Pyramids

The high-resolution TIFF scans contain millions of pixels, and their channel displacements can be much larger than the [-15, 15] window used for the JPEG examples. Instead of searching over every possible displacement at full resolution, I used a coarse-to-fine image pyramid.

Why the pyramid helps

At a smaller resolution, a large physical displacement becomes a much smaller pixel displacement. The algorithm can therefore first find the approximate alignment cheaply and then refine it at higher resolutions. This keeps the search local at the expensive full-resolution levels while still allowing the algorithm to recover large overall shifts.

Part 03

When Brightness Becomes Misleading

Most of the images aligned well using raw pixel intensities, but the Emir image revealed an important limitation of this approach. The same physical object can have very different brightness values in different color channels. This means that two corresponding pixels do not necessarily have similar numerical intensities.

Why does Emir fail?

The Emir's blue robe appears very bright in the Blue exposure but much darker in the Red exposure. Raw-intensity NCC compares these brightness patterns, so it can prefer an incorrect displacement even though the physical robe occupies the same location in both images.

What went wrong

NCC is useful because it normalizes the brightness and contrast of the two images, but it still depends on the relationship between their intensity patterns. For the Emir's robe, that relationship is misleading: a bright region in one channel can correspond to a dark region in another. The algorithm therefore receives a stronger similarity signal from the wrong location.

Bells & Whistles · Better Features

Edge Detection with Sobel Gradients

To make the alignment less dependent on absolute brightness, I changed the features being compared. Instead of applying NCC directly to the raw pixel values, I applied a Sobel filter to each channel first. The resulting gradient magnitude maps emphasize edges and changes in intensity rather than the intensity values themselves.

01 · Input

Each monochrome color channel is processed independently.

02 · Sobel

Horizontal and vertical image gradients are used to create an edge-strength representation.

03 · Align

NCC is applied to the edge maps using the same coarse-to-fine pyramid.

Sobel edge detection allows the algorithm to focus on structural boundaries such as the robe, face and surrounding architecture instead of their absolute brightness.

Why edge filtering works

The Sobel operator measures how quickly intensity changes across an image. Although the Emir's robe changes dramatically in brightness between the color channels, its physical boundaries remain in approximately the same locations. By aligning these structural features instead of raw intensities, the algorithm becomes less sensitive to the different appearances created by the color filters.

Final Takeaway

This project started with a relatively simple alignment problem, but the results showed how much the choice of representation matters. Exhaustive search worked well for the smaller images, while the image pyramid made it practical to align the much larger TIFF scans. The Emir failure then showed that raw pixel intensity is not always a reliable feature for matching different color channels. Using Sobel edges provided another way to describe the images based on their structure, allowing the alignment procedure to handle this difficult case more effectively.
